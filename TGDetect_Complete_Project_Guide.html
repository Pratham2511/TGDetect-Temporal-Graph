🏷 Ground-Truth Labeling Mechanics

In CTU-13, the Label column contains over 50 distinct strings (e.g. flow=From-Botnet-V52-1-TCP-Attempt). TGDetect avoids brittle exact string matches: 

label = 1 if "botnet" in label_str.lower() else 0

Two background policies are supported:
• benign (default): Treats Background + Normal as label 0 (realistic class imbalance: 0.87% positive).
• drop: Discards background traffic, evaluating pure Normal vs Botnet.

🛡 Malformed Data Handling

The parser in parsers.py implements strict error isolation:

  • Truncated lines with fewer than 15 columns are silently skipped.
  • Unparseable timestamp strings are safely ignored without crashing the stream.
  • Empty ports or hex representations (e.g. 0x0035) are safely coerced to integer or NaN.
  • Missing IPs abort only that single event record.

Part 7 — 🕸 How TGDetect Builds a Graph

Graph Concepts Explained from Scratch

Node (Entity)

An individual actor or object in the network. In TGDetect, nodes are unique IP addresses (e.g. ip:147.32.84.165).

Edge (Relation)

A communication link connecting two nodes. In TGDetect, each NetFlow creates a directed edge: Source IP → Destination IP.

Directed Multigraph

Edges have direction (who initiated contact), and two nodes can share multiple distinct edges over time across different ports.

🧠 Simple Explanation
If Computer A sends a file to Computer B, Computer A is a dot (source node), Computer B is a dot (destination node), and the data transfer is an arrow pointing from A to B (edge). The arrow carries a backpack of information (features): how many bytes were sent, how long it took, what port was used, and the exact second it happened.
⚙ Technical Explanation
TGDetect constructs a spatiotemporal heterogeneous multigraph. For network telemetry (CTU-13), all entities are IPv4 addresses. Crucial Design Decision: Node features are intentionally set to a 1-dimensional constant vector (all ones). Why? Because every node in CTU-13 is an IP address; using node degree or malicious packet ratios would cause catastrophic label leakage during training. Therefore, 100% of the discriminative signal is placed onto the 37-dimensional edge feature vector, forcing the GNN to learn communication topology rather than memorizing individual IP identities.
🔍 TGDetect 37-Dimensional Edge Feature Breakdown
Every edge carries a 37-dimensional normalized feature vector extracted per-row in temporal.py:
  • 9 Scaled Numerics & Rates (log1p transformed): Duration, Total Bytes, Source Bytes, Destination Bytes, Total Packets, Bytes-per-Packet, Bytes-per-Second, Packets-per-Second, and Source-Byte-Ratio.
  • 9 Protocol One-Hot Features: 8 vocabulary tokens (tcp, udp, icmp, arp, rtp, ipv6-icmp, igmp, udt) + 1 "other".
  • 7 Direction One-Hot Features: 6 direction tokens (->, <-, <->, ?>, ?<, ?->) + 1 "other".
  • 8 TCP Connection State Flags: Binary flags indicating connection states and TCP flags (CON, INT, URP, S, F, R, A, P).
  • 10 Port Service Buckets: Ephemeral vs well-known flags for source and destination ports, plus dedicated service buckets for DNS (53), HTTP (80/8080), HTTPS (443), SMTP (25/465/587), IRC (6660-7000), and Other. (Raw port integers are strictly avoided to prevent the model from memorizing scenario-specific C2 ports).
  • 1 Relative Time Feature: Normalized position within the sliding time window (t - window_start) / window_duration.

"TGDetect avoids label leakage by keeping node features neutral and placing rich, 37-dimensional flow descriptors directly on the edges—training our GNN to recognize attack communication patterns rather than memorizing specific IP addresses."

Part 8 — ⏱ What Makes Our Graph Temporal?

🧠 Simple Meaning
A regular photograph shows where everything is at one frozen moment. A video shows how things move over time. A static graph is just a photograph. TGDetect’s temporal graph is a high-speed video of network communications, slicing time into 60-second frames so our neural network can watch the attack unfold frame by frame.
⚙ Technical Meaning
TGDetect processes temporal graphs via discrete sliding-window snapshot sequences. Events are chronologically indexed by epoch timestamp ts. The TemporalSnapshotBuilder divides the timeline into overlapping windows of duration W = 60s with stride S = 30s. For each window t, a snapshot graph G_t = (V_t, E_t) is formed from active flows. Spatial graph convolutions encode each snapshot into node embeddings, which are then passed sequentially through a Gated Recurrent Unit (GRU), maintaining a hidden state vector that carries structural memory forward in time.
🔍 Honest Implementation Reality vs. Future Research
CURRENT IMPLEMENTATION: Discrete temporal snapshots (60s sliding window, 30s stride) combined with recurrent GRU state tracking. This is computationally robust, handles millions of edges efficiently, and avoids memory explosion.

FUTURE RESEARCH ROADMAP: Continuous-time dynamic graph neural networks (e.g. TGN, JODIE, DyRep) using continuous-time memory modules and learnable time encodings. These are active research frontiers, not currently deployed in production.
🎤 Presentation Line
"Our graph is temporal because we slice network telemetry into overlapping 60-second sliding windows, using a GRU recurrent layer to track how node behaviors and communication structures evolve over time."

Part 9 — ⚔ How TGDetect Reconstructs Attack Chains

An individual alert indicates a suspicious event; an attack chain reconstructs the entire multi-hop operational campaign across time. TGDetect implements three distinct strategies in backend/graph_builder/attack_tracker.py:

STRATEGY 1 chain_id

Ground-Truth Grouping: Groups malicious events using pre-annotated scenario IDs. Primarily used in benchmark evaluations and structured datasets (e.g. Mordor) to validate graph reconstruction accuracy.

STRATEGY 2 causal_parent

Causal Link Walking: Implements Disjoint-Set Union (Union-Find) with path compression across explicit execution pointers (e.g. process parent IDs). Assembles deterministic trees of causal interaction.

STRATEGY 3 entity_time

Heuristic Spatiotemporal Expansion: Seeds on detected malicious events and expands outward to all events sharing source or destination IP entities within a 24-hour temporal sliding window, up to 2 graph hops. Requires zero ground-truth labels!

🧠 Simple Explanation
If a burglar visits five different houses in one evening, the police don't treat them as five unrelated events. They connect them by suspect vehicle and time of night. TGDetect does the exact same thing: when it spots a suspicious network flow, it immediately looks backward and forward in time, grabbing all communications involving that machine over the last 24 hours and tying them into one clean, chronological incident report.
🎤 Presentation Line
"TGDetect reconstructs multi-step attacks using three complementary strategies, notably our unsupervised entity-time algorithm which clusters related events across 24-hour windows without needing prior ground-truth labels."

The attacker's tactical objective — what they are trying to accomplish at this phase of the attack.

TECHNIQUE (The "How")

The specific method or technology the attacker uses to achieve that tactic.

Part 11 — 🤖 How the TGDetect Model Works

The core detection engine of TGDetect is a custom Temporal Graph Neural Network (TGNN) implemented in backend/models/tgnn.py. It is intentionally lightweight, containing exactly 38,787 trainable parameters.

📐 Exact Layer Specifications
Input Node Dimensionin_channels = 1 (scalar type-only, leakage-free)
Input Edge Dimensionedge_dim = 37 (flow rates, ports, proto, state, time)
GNN Spatial Layers2 × SAGEConv(64, 64) + Linear Edge Encoders
Edge Message PassingCustom bidirectional mean-aggregation onto both endpoints
Recurrent Temporal Layer1 × GRU(input_size=64, hidden_size=64, batch_first=False)
Headline Output Headedge_classifier = Linear(128, 1) (concat of endpoints)

Why GraphSAGE + GRU?

🧠 Simple Meaning

Part 13 — 📉 Loss Functions & Extreme Class Imbalance

⚙ Loss Function Formulation
TGDetect employs torch.nn.BCEWithLogitsLoss with positive class weighting: 
loss_fn = nn.BCEWithLogitsLoss(pos_weight=torch.tensor([48.32]))
Why BCEWithLogitsLoss?
1. Numerical Stability: Combines a Sigmoid activation and standard Binary Cross Entropy into a single layer, leveraging the log-sum-exp trick to prevent underflow/overflow on extreme logits.
2. Severe Class Imbalance: In real network traffic, attacks represent less than 1% of flows (in CTU-13 Scenario 47, only 9,256 out of 1,068,851 flows are malicious — a 0.87% base rate). Without pos_weight, a naive model predicting "benign" for every flow achieves 99.13% accuracy while detecting zero attacks! pos_weight=48.32 scales the loss penalty for missed malicious flows by ~48×, forcing the model to aggressively prioritize threat detection.

Complete Technical Glossary

APT (Advanced Persistent Threat): A sophisticated, prolonged cyberattack campaign where intruders establish an undetected presence on a network.

NetFlow: A network protocol developed by Cisco for aggregating packet streams between IP endpoints into summary flow records.

GraphSAGE: Sample and Aggregate — an inductive GNN architecture that learns spatial aggregation functions over local node neighborhoods.

GRU (Gated Recurrent Unit): A gating mechanism in recurrent neural networks that models temporal dependencies with reset and update gates.

ROC-AUC: Area Under the Receiver Operating Characteristic curve; evaluates threshold-free binary ranking ability.

PR-AUC: Area Under the Precision-Recall curve; evaluates positive-class detection under severe class imbalance.

Recall @ 1% FPR: The percentage of actual attacks detected when the false alarm rate is fixed at exactly 1%.

Label Leakage: An error where target ground-truth information is inadvertently included in input training features.

Disjoint-Set Union (Union-Find): A data structure tracking partitioned elements into disjoint subsets, used in causal chain reconstruction.

Inductive Learning: The ability of a machine learning model to generalize to completely unseen nodes or graphs at inference time.

Single Source of Truth: An architectural pattern ensuring all views read from a single authoritative state store (DatasetContext).

BCEWithLogitsLoss: Binary cross entropy loss with integrated sigmoid activation and optional positive class weighting.
